## Contexto
Para ler os valores de temperatura e humidade através de um sensor DHT20, o sistema necessita de uma interface de comunicação física e de um protocolo compatível com o sensor e com o microcontrolador ESP32-C6.

## Decisão
Decidimos utilizar o barramento I²C em modo master (usando a nova API `i2c_new_master_bus()` do ESP-IDF) para comunicar com o sensor DHT20.

## Justificativa
* O sensor DHT20 apenas suporta nativamente a interface I²C para comunicação de dados.
* O protocolo I²C utiliza apenas duas linhas de sinal (SDA e SCL) mais alimentação, minimizando a ocupação de pinos GPIO do ESP32-C6.
* O ESP-IDF v6.x disponibiliza uma API robusta baseada em *handles* (`i2c_master_bus_handle_t`) para gerir a inicialização do barramento e os dispositivos associados de forma thread-safe.
* Esta configuração permite enviar o comando de medição (`0xAC, 0x33, 0x00`) e ler a trama de dados de 7 bytes contendo temperatura, humidade e CRC.

## Alternativas consideradas
* **Comunicação sem fios:** Não foi considerada viável pois exigiria um nó/hardware adicional, aumentando a complexidade e o custo em comparação com a ligação direta do sensor DHT20.
* **UART:** Não é suportada pelo hardware do sensor DHT20.
* **SPI:** O sensor DHT20 não disponibiliza interface SPI.

## Consequências
* É necessário garantir o correto pull-up das linhas SDA e SCL (configurado via software no driver com `.flags.enable_internal_pullup = true` ou recorrendo a resistências externas se necessário).
* A tarefa de aquisição deve respeitar o tempo de conversão do sensor (mínimo de 80 ms entre o comando de medição e a leitura dos dados).
* O programa deve implementar a verificação de integridade dos dados lidos via algoritmo CRC8 e tratar possíveis timeouts ou falhas de comunicação no barramento sem bloquear o sistema.
* O barramento I²C 0 pode futuramente ser partilhado com outros periféricos, desde que possuam endereços I²C distintos.
